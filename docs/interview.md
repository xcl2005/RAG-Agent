# 面试讲解稿

## 1. 你这个项目是做什么的？

这是一个企业知识库 RAG Agent。用户可以把大量 PDF、Word、Markdown、TXT 等资料导入系统，系统会自动解析、切分、向量化和建索引。用户提问时，系统先进行混合检索和 rerank，再让大模型基于检索到的资料生成带来源引用的回答。

## 2. 为什么不能直接把所有资料发给大模型？

因为资料量可能远超模型上下文窗口，而且每次都传全部资料成本很高、速度慢、噪声大。RAG 的思路是先从知识库中检索最相关的片段，再把少量高相关内容交给大模型回答。

## 3. RAG 流程是什么？

我的实现流程是：文档解析 → chunk 切分 → embedding → 向量库入库 → 用户提问 → query rewrite → 向量召回 + 关键词召回 → RRF 融合 → CrossEncoder rerank → 证据判断 → 生成带引用回答。

## 4. chunk size 怎么选？

chunk size 太小，检索更精确，但上下文可能不完整；chunk size 太大，上下文完整，但噪声更多，embedding 表达不精准。我默认使用 900 字符、150 overlap。对于中文短文档可以调小到 700 左右；对于论文或报告可以调大到 1200 左右。

## 5. overlap 有什么用？

overlap 是为了避免切片边界导致信息断裂。比如一个概念的定义在上一个 chunk，解释在下一个 chunk，如果没有 overlap，检索到其中一个片段时可能缺少上下文。

## 6. 为什么要同时做向量检索和关键词检索？

向量检索擅长语义相似，关键词检索擅长精确匹配。比如用户问“系统如何降低幻觉”，向量检索可以找到“证据门控、来源引用”；但如果用户问的是错误码、表名、政策编号，关键词检索更可靠。因此我用了 hybrid retrieval。

## 7. RRF 是什么？

RRF 是 Reciprocal Rank Fusion，用来融合多个排序结果。它不直接依赖不同检索器的原始分数，而是根据排名加权，所以适合融合向量检索和关键词检索这种分数尺度不同的结果。

公式大概是：

```text
score(doc) = sum(1 / (k + rank))
```

排名越靠前，加分越高。

## 8. rerank 为什么有效？

第一阶段检索通常是为了速度，只能粗排。CrossEncoder reranker 会把“问题”和“候选片段”一起输入模型，直接判断这个片段能不能回答问题，因此排序更精细。但它慢，所以只对 top 20 之类的小候选集做二次排序。

## 9. 怎么降低幻觉？

我做了几层约束：

1. prompt 要求只基于上下文回答。
2. 关键结论必须引用来源。
3. 检索结果为空或低于阈值时拒答。
4. temperature 设为 0.1。
5. API 返回 sources，方便人工核查。

## 10. 这个 Agent 和普通 RAG 有什么区别？

普通 RAG 可能就是一个函数：检索，然后生成。这个项目用 LangGraph 把流程拆成多个节点：query rewrite、retrieve、grade evidence、generate answer。这样更容易扩展工具调用、多轮状态、人工确认和复杂工作流。

## 11. 如果用户问的问题资料里没有怎么办？

系统会在 evidence gate 阶段判断。如果没有候选片段，或者相关性分数低于阈值，就返回“根据当前资料无法确认”，而不是让模型自由发挥。

## 12. 如果资料越来越多，怎么优化？

可以从几方面优化：

- 文档增量更新，避免全量重建。
- embedding 批处理。
- 使用元数据过滤，比如部门、文件类型、时间。
- 限制 rerank 数量。
- 增加缓存。
- 根据业务做权限控制。
- 把 SQLite FTS 换成 Elasticsearch / OpenSearch。

## 13. 你实际负责哪部分？

可以按你真实掌握程度说：

> 我主要负责文档解析、chunk 切分、向量入库、混合检索和问答 API 的实现。对于 LangGraph 和 rerank 部分，我完成了基础集成，并通过样例数据验证了完整链路。

不要吹成“大规模生产落地”，可以说是“工程实践型项目”。

## 14. 简短项目介绍，适合面试开场

我做了一个企业知识库 RAG Agent，主要解决大量内部文档无法直接交给大模型的问题。系统会先把 PDF、Word、Markdown 等资料解析并切分成 chunk，然后用 embedding 写入 Qdrant，同时用 SQLite FTS5 建关键词索引。用户提问时，系统会进行向量召回和关键词召回，用 RRF 融合，再通过 CrossEncoder rerank 做二次排序，最后让大模型基于检索上下文生成带引用的回答。为了降低幻觉，我加了证据门控、来源引用和低 temperature 策略。
