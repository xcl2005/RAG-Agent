# 面试准备

先完成 [学习路线](learning-path.md) 的基础题，再做本页演练。参考答案默认藏在练习 CLI 的 `--reveal` 后，
不要求逐字背诵。能指向函数、测试和自己的实验，才比一句“熟悉 LangGraph”更有说服力。

## 90 秒介绍，不照背经历

1. 15 秒：解决什么问题？文档问答为什么需要检索和来源？
2. 25 秒：主链路？入库、检索、门控、预算整理、生成、引用检查。
3. 30 秒：你亲自改了什么？打开一个实际写过的测试，讲失败输入、原因与修复。
4. 20 秒：结果与限制？给实验范围和负面案例，不把开发集检索指标叫线上准确率。

目前没亲手改过的部分，说正在学习，完成实验后再改个人表述。更详细的准确边界见
[简历指南](resume-guide.md)。

## 一次 20 分钟模拟面试

| 时间 | 面试官问题 | 你要拿出的证据 |
|---|---|---|
| 0–2 分钟 | 请介绍项目，不要报一串技术名词。 | 90 秒说明，区分入库与提问时检索。 |
| 2–5 分钟 | 为什么不把全部文件直接塞给大模型？ | chunk、检索、噪声与预算；展示 `build_context`。 |
| 5–8 分钟 | 为什么需要 FTS5？RRF 为什么不加原始分数？ | 错误码/同义词例子，手算一个 RRF。 |
| 8–11 分钟 | 已找到正确文件却拒答，先看哪里？ | `p04` 报告：来源排名、覆盖度、阈值。 |
| 11–14 分钟 | `[S1]` 合法代表内容真实吗？ | 编号校验反例，不声称逐句语义验证已实现。 |
| 14–17 分钟 | Qdrant 写成功而 SQLite 失败怎么办？ | 写入顺序、权威回表、孤儿向量、补偿清理。 |
| 17–20 分钟 | 哪项还没做，下一步怎么证明有用？ | 独立测试集、query-aware 句窗/语义门控及其代价。 |

每次只改进一个最薄弱点。录音后检查：有没有跳过问题、把假设说成事实、只讲结论不给证据？
原理、代码、实验、边界分别自评 0–3，0 不会，1 能复述，2 能结合代码，3 能独立修改验证。
工具保存的是本人判断，不是自动评分或录取预测。

## 必须讲准确的几个区别

- 有界 Workflow 不等于自主执行任意任务的通用多 Agent 系统。
- 当前门控是 reranker / dense / sparse 三路独立阈值 OR；RRF 只管排序。
- OR 可以减少单路误拒答，也可能错误放行；见 [实验记录](experiment-notes-2026-09.md)。
- 空正文是模型生成失败，不是证据不足；检查 finish_reason、reasoning 与输出 token 预算。
- SQLite checkpoint 保存多轮状态，不等于内存 JobRegistry 能跨重启恢复任务。
- SSE 是节点事件，不是模型 token 增量；MCP 是只读接口，不是第二套编排引擎。

## 高频追问

面试前至少能现场解释：

- 为什么 workflow 没有过时，哪些节点交给模型、哪些必须由确定性代码控制。
- 为什么首轮保留原始问题、重试优先新变体，以及多查询为什么使用递减权重。
- 为什么不能直接相加 dense、FTS 和 CrossEncoder 原始分数。
- 弱证据为何重试、最多重试几次、最坏模型调用数如何受控。
- 引用校验保证了什么，又没有保证什么。
- Qdrant 与 SQLite 不存在分布式事务时，怎样保证“可见结果正确”。
- 为什么 MCP 只读，为什么当前不增加 A2A、多 Agent 或 GraphRAG。
- JobRegistry、共享 API Key、引用语义和公网部署有哪些真实限制。

## 5 分钟演示

先跑 `python scripts/eval_portfolio.py`，即使没有 Key、Docker 或模型网络也可展示。打开 `p04` 与 `n08`，
分别讲误拒答和错误放行，再运行 `python -m pytest tests/test_prompts.py -q`，讲一个自己理解的测试。
本地服务可用时双击 `start.cmd`，展示来源和“整理证据上下文”节点。

完整在线演示可采用以下顺序；只使用虚构资料，勿展示身份证、成绩单或真实 Key：

1. 上传资料，展示 `job_id`；再通过同一路径 CLI/API 导入展示内容与索引指纹一致时的幂等跳过。
2. 提一个可回答问题，展示节点级 SSE、来源 quote 和 trace。
3. 提一个资料外问题，展示有界重试和拒答。
4. 复用同一 `thread_id`，展示多轮状态。
5. 运行一个测试和一轮离线评测，说明它们各自防止什么回归。

不要声称“零幻觉”“生产级高并发”“百万文档”或未经报告证明的提升数字。

如果被问“用了 AI 吗”，如实说明辅助范围，然后演示你能独立解释和修改的部分。
不编造提交历史，也不假装没有参考代码；展示判断、验证和持续改进能力。
